### SMS-089 — REFUTED (restart markers cannot desynchronise a walk that ends at SOF/SOS)

The code flaw exists only in the abstract: `SMS_ArtworkJPEGSize` (`src/SMS_Artwork.c:54-71`) does assume every marker it *reaches* carries a 2-byte length (`:61-63`, `:71`), and it has no special case for RST0–RST7 (0xD0–0xD7) or TEM (0x01). The finding's claimed consequence — "a baseline JPEG written with a restart interval (DRI) therefore desynchronises the walk … and the walk almost always returns 0 … the artwork silently never loads" — is defeated by the walk's own termination points and by JPEG segment order:

1. **The walk returns before any entropy data.** At `:64-68` it returns the verdict as soon as it reaches SOF0 (0xC0); at `:60` it returns 0 on SOS (0xDA). In a valid JPEG the frame header (SOF) always precedes the scan (SOS), and restart markers exist only *inside* the entropy-coded scan data after SOS. There is therefore no point in a valid file at which this walk is positioned on an RST or TEM marker.
2. **DRI itself is handled correctly.** A restart-interval file announces the interval with a DRI segment (0xDD), which *is* length-bearing (length 4). The walk reads its length at `:61-63` and skips it at `:71`, then proceeds to SOF and returns — exactly as for a file without DRI. The decoder confirms this structure: `src/SMS_JPEG.c:526-533` parses DRI as a length-bearing segment (`_segment` + a 2-byte size), its SOS case at `:534ff` requires a frame to have been parsed already (`!lfFrame … goto end`), and RST markers are recognised (`MK_RST`, `src/SMS_JPEG.c:54`) only in scan processing.
3. **No alternative route to an RST/TEM in the header area exists in-tree.** APPn and other header segments are skipped by their lengths, never scanned byte-by-byte, so marker-like bytes inside a segment payload (e.g. an embedded thumbnail) are never interpreted as markers.

What survives: nothing of the stated user-visible defect. A hand-crafted file that inserted a standalone marker *before* SOF would desynchronise the walk — but such a file is not "a baseline JPEG written with a restart interval", and no evidence was found that the in-tree decoder accepts that placement either (its header loop likewise dispatches on length-bearing segment types). The proposed `continue` for 0xD0–0xD7/0x01 is harmless, but as a fix for valid DRI files it fixes a rejection that does not occur.

### SMS-123 — REFUTED (reopened claim: a *reachable* off-by-one OOB read does not exist at this pin)

**What is literally true in the original finding** (re-verified): in both decoders the table is indexed before the check — `hcb_2_quad_table[cb][offset].bits` is read at `src/SMS_AAC.c:6464` and `hcb_2_pair_table[cb][offset].bits` at `:6531`, while the only range tests are at `:6467` (`if (offset > hcb_2_quad_table_size[cb]) return 10;`) and `:6534`. The ordering defect as a piece of code hygiene stands.

**The reopened question** is whether the file-influenced `offset` can actually reach an index past the *actual* table end at those use sites. It cannot, on any codebook, by script proof:

1. `cw` is bounded by construction: `cw = SMS_SHOW_UBITS(r, ld, hcbN[cb])` (`:6458/:6525`), with `hcbN` = {5,5,5,5,5,6,5} for codebooks {1,2,4,6,8,10,11} (`src/SMS_AAC.c:2136-2138`), and `SMS_SHOW_UBITS` is `SMS_NEG_USR32(cache, num)` = `(uint32_t)cache >> (32 - num)` (`include/SMS_Bitio.h:35`, `include/SMS.h:68`) — a value in `[0, 2^num)`, exactly indexing the 32-entry (64 for cb10) first-stage tables.
2. `offset = hcb_table[cb][cw].offset + SMS_SHOW_UBITS(r, ld, extra_bits)` (`:6459,6463` / `:6526,6530`), where the added value is in `[0, 2^extra_bits)` by the same macro. So the maximum reachable offset for a codebook is `max over first-stage entries of (offset + 2^extra_bits − 1)`, computable entirely from the static tables — the file chooses *which* entry and *which* in-segment value, nothing more.

**Interlock arithmetic (as assigned, verified in its own terms):**

- **(a) Reorder-only fix — threshold arithmetic: TRUE, reachability: NO.** Moving the existing test (`offset > declared`) above the use would *admit* (pass without error) every offset ≤ declared.
