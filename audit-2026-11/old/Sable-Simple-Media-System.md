### SMS-001 / Two complete IOP-module delivery systems ship in one ELF: legacy hex-dump blob + BDM IRX set / Category 2
- **Location(s):** Simple-Media-System/src/SMS_Data.c:20 (16,728 lines, 1,634,985 bytes); Simple-Media-System/include/SMS_Data.h:14-49; Simple-Media-System/src/SMS_IOP.c:183-185,472,576-601; Simple-Media-System/Makefile:48-59; Simple-Media-System/irx/ (43 files)
- **Problem:** `g_DataBuffer` is a 266,425-byte (sum of the 17 `SMS_*_SIZE` constants, READ) compiled-in blob holding a second, legacy set of IOP modules (PS2ATAD 11,821 + PS2HDD 24,953 + PS2FS 50,405 + USBD/USB_MASS + PS2IP 67,061 + PS2SMAP + PS2HOST 16,349 + SMB 19,641 + CDVD 20,093 + …), while the BDM=1 build *also* embeds the modern `irx/*.irx.xz` set (bdm, ata_bd, usbd, smbman, mcman…). Storage, network and USB therefore exist twice, in two formats, selected by boot path.
- **Fix:** Pick one delivery system per module. For any module the BDM path already provides, delete its copy from `SMS_Data.c` and its `*_OFFSET/*_SIZE` pair; keep the legacy blob only for modules provably loaded on a boot path BDM cannot serve, and name those paths in one comment.
- **Benefit:** *est.* up to ~100–200 KB of ELF `.data` and ~10,000 source lines if the duplicated ATAD/HDD/FS/USB/SMAP modules go; exact figure depends on which legacy boot paths are still supported — that decision is the work.
- **Effort:** L. **Risk:** High (boot paths; hardware test every supported boot device). **Confidence:** High (READ — both sets and both loaders read; which legacy paths are still *used* is INFERRED).
