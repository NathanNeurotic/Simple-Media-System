## #1 Converter 'Upload ... to Version Release' steps exit 0 after all 12 uploads fail (stable tag can ship without converter binaries, green check)
- issue: 0
- severity: medium
- category: ci
- files: ['.github/workflows/sms-converter.yml', 'tools/test_converter_publication.py']
- reproduced: True
- confidence: 0.95
- risk: None for the PS2 binary. Behavioural change only on v* tag pushes: a converter upload that cannot complete now turns the job red instead of green.

### evidence
.github/workflows/sms-converter.yml lines 157-170 (Windows), 172-184 (Linux), 301-314 (Win7): `for i in {1..12}; do if gh release upload "$GITHUB_REF_NAME" ... --clobber; then echo ...; break; fi; echo "Waiting..."; sleep 10; done` with nothing after the loop. The last command executed is `sleep 10`, so the step succeeds when every attempt failed. The rolling-release steps in the same file were already fixed to `exit 0` on success and `exit 1` after the loop; the tag path was not, and tools/test_converter_publication.py only extracts the three '... to Rolling Release' steps. Ran scratchpad/hunt-ci-docs-release/version_release_repro.py (extracts each real step body, runs it under `bash -eo pipefail` with gh() always returning 1 and sleep stubbed): all three printed `gh always fails -> step exit code 0; gh attempts=12`. The path has never run in production (the workflow was added 2026-07-26, after v3.0.0-rev1), so the next `v*` tag is its first use; the release is created by a different workflow (compilation.yml line 263-269) at the end of a ~2 min job, so a slow or failed player build makes this the likely outcome.

### fix
In each of the three Version Release steps: replace `break` (lines 166, 180, 310) with `exit 0`, change the trailing `sleep 10` to `if [ "$i" -lt 12 ]; then sleep 10; fi`, and add after `done`:
        echo "Failed to publish <asset> to release $GITHUB_REF_NAME after 12 attempts" >&2
        exit 1
Also add `shell: bash` to the Linux step (line 172) for consistency with the others. Trial patch applied to a private copy (sms-converter.patched.yml): repro now prints exit code 1 for all three, and tools/test_converter_publication.py against the patched file still reports '33 shell controls ... passed' (WSL).

### test
python3 scratchpad/hunt-ci-docs-release/version_release_repro.py .github/workflows/sms-converter.yml must print exit code 1 for all three steps. Optionally extend STEPS in tools/test_converter_publication.py with the three Version Release step names and one 'upload-failure -> non-zero' case each (the fake gh already models failing uploads; the header assertion on the master-push condition must be skipped for these).
