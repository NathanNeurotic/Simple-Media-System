Settings Reference

This is the full reference for the SMS settings menu — every option, grouped exactly the way SMS groups them, with what each one does and the values it accepts. If you only want to turn a storage device on, jump to Device settings; if you're tuning subtitles or the picture, see Player settings and Display settings.

ℹ How to reach the settings menu
The settings menu is the same SMS menu you use for saving and quitting. Open it from the browser, then pick one of its top-level entries. Each entry opens a sub-menu of options. On a toggle, Cross flips it between on and off; on a value item, Left/Right cycles the value. Triangle goes back up a level. Nothing is committed to storage until you run Save settings (see Saving your settings) — so you can experiment freely and just not save.

The settings menu at a glance

The top level of the SMS menu has these entries. The first four open the option sub-menus documented on this page; the last four are actions.

Device settings — storage & network

This is the menu you care about most on this fork: it is where you turn storage devices on. Each device has an Autostart toggle (whether it starts automatically at boot), and — when the device is not currently running — a matching Start … support item appears at the bottom of the menu so you can bring it up right now without rebooting.

Autostart toggles

Each toggle shows on or off. On a clean install (no saved settings) every one of these is off — SMS auto-starts nothing, so you enable only the devices you actually use. Once you save, your choices persist across reboots.

OptionDevice it startsValues
Autostart HOST ( ps2dev )The ps2dev host: stack (ps2client on a PC). One of three mutually exclusive network rows.on / off
Autostart SMBThe SMB1/CIFS share client. One of three mutually exclusive network rows. See Network Setup.on / off
Autostart USBUSB mass storage (massN:). See USB.on / off
Autostart HDD APAThe internal HDD via the classic APA/PFS path (hdd0:); SMS lists the drive's PFS partitions so you can pick one. See Internal HDD.on / off
Autostart HDD BDMThe internal HDD via ATA as a BDM massN: device — this is the exFAT path added by this fork. See Internal HDD.on / off
Autostart MX4SIOThe MX4SIO microSD adapter over SIO2 (massN:). The headline feature of this fork. See MX4SIO.on / off
Autostart i.LINKAn i.LINK (IEEE 1394 / FireWire) drive as a BDM massN: device. See i.LINK.on / off
Autostart MMCEAn MMCE device (SD2PSX / MemCard PRO2) in the memory-card slot (mmce0: / mmce1:). See MMCE.on / off
Autostart UDPFSThe folder-served UDPFS network drive (udpfs:). Mutually exclusive with SMB/host for that boot. See UDPFS.on / off
⚠ Shared resources — choose one member of each pair
  • MX4SIO and MMCE both use the SIO2 / memory-card-slot bus. Only one can be active at a time — enable the one you're using, not both.
  • HDD APA and HDD BDM both own the internal ATA bus. Pick one; whichever starts first owns the bus. Use HDD APA for a classic APA/PFS drive, or HDD BDM for a modern exFAT drive.
  • Network (SMB/host) and UDPFS load different stacks for the one Ethernet controller. Whichever starts first owns it until reboot. Enable one, not both.
See Devices Overview for the full picture.

"Start … support" — bring a device up now

When a device isn't running yet, a matching item appears at the bottom of the Device menu. Selecting it starts that device immediately, so it shows up in the device row without a reboot. Once the device is up, its item disappears from the list. The wording matches each device:

  • Start SMB server support (shown when an SMB server is configured)
  • Start HOST ( ps2dev ) support
  • Start USB support
  • Start HDD support (APA)
  • Start HDD BDM (ATA / exFAT)
  • Start MX4SIO support
  • Start i.LINK support
  • Start MMCE support
  • Start UDPFS network drive

The Device menu also ends with a Refresh connections item, which re-probes the running devices — handy after hot-swapping a card or drive so its contents are re-read.

ℹ Autostart vs. Start-now
Autostart decides what comes up automatically at every boot (and is remembered once saved). Start … support is a one-shot "turn it on for this session" that doesn't change the Autostart toggle. A common flow: leave everything off, use Start MX4SIO support to test, then — once happy — flip Autostart MX4SIO on and save.

⚠ HD modes and the background
SMS supports higher-resolution modes (including a 720p framebuffer) via these advanced settings, but on this fork a full-screen wallpaper at 720p is still being tuned. If you switch to an HD mode and the desktop background looks wrong, drop back to a standard mode. Standard NTSC/PAL is the tested, reliable path for now.

ℹ Palette / colour items
The colour options (Active border color, Text color, Selection bar color, and the subtitle colours in the Player menu) pick from SMS's 16-entry palette. Cycle the value to preview each colour live in the panel it affects, so you can match your skin. See Themes & Skins for the palette itself.

Saving your settings — and where they go

Nothing you change in the menus is permanent until you run Save settings from the top level of the SMS menu. Until then you can change anything and simply not save. There is also a button shortcut on some builds (Select+Square) that saves settings from the browser.

Make your changes

Set your Autostart toggles, colours, subtitle look, and so on in the sub-menus. Try devices with Start … support first if you like.

Run Save settings

Back out to the top of the SMS menu (Triangle), select Save settings, and confirm.

Reboot to confirm

Your Autostart choices and preferences come back on the next boot.

ℹ Where the config is stored (and the fork's twist)
Stock SMS saves its configuration to the memory card at mc0:/SMS/SMS.cfg. On this fork the config simply follows the boot device, card or no card: launched from USB, HDD, MX4SIO, MMCE, i.LINK or writable UDPFS, SMS writes SMS.cfg next to the ELF on that same device, so the settings travel with the drive you booted from. Either way, one Save settings is all it takes. Deleting the config file gives you clean defaults again — where nothing auto-starts. The separate SMS.smb server list follows the same directory. IPCONFIG.DAT is the one exception: it goes to mc0:/SYS-CONF/ when a card is fitted, because that is where the PS2 browser and other titles look for it, and falls back to the ELF's folder when there is no card.
⚠ Clean defaults auto-start nothing
On a first boot or after clearing the config, no storage device is started automatically. This is deliberate on this fork: you turn on exactly what you need. If SMS boots and you don't see your device, that's expected — enable its Autostart (or use Start … support), then Save settings.

Why is there both "HDD APA" and "HDD BDM" — aren't they the same drive?

They are the same physical internal HDD, but reached two different ways. HDD APA uses the PS2's classic APA/PFS filesystem and reads media from the PFS partitions on hdd0: — the traditional SMS route. HDD BDM reads the drive as a modern exFAT volume over ATA, appearing as a massN: device like USB or MX4SIO — the path this fork adds so you can use a normally-formatted drive. They share the internal ATA bus, so only one can be active; whichever starts first owns it. Choose the one that matches how your drive is formatted. See Internal HDD.

I enabled Autostart MX4SIO but MMCE stopped working (or vice-versa)

That's expected. MX4SIO and MMCE both drive the SIO2 / memory-card-slot bus, so SMS can only run one of them at a time. Turn off the Autostart for the one you're not using, enable the one you are, and save. If you need to switch during a session, you can turn one off and use Start … support for the other.
