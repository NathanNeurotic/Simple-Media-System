MPEG-2/AC3 opening freeze — #29

The reporter's MPG freezes at container opening on an SCPH-77004/USB setup and worked in 2.9rev4. Probing, cursor restoration, short-read handling, metadata retries and progress exits have fixes with host regressions. Retest the unchanged reporter file on the same console/source using standard and DIAG builds. Record the last label: MPEG probing is E48 probe mpg; include its text because diagnostic numbers can overlap other phases. PR #55 fixes seeks at or above 2 GiB landing on end-of-file on BDM drives (USB, MX4SIO, i.LINK and HDD BDM; at the reporter's build this made the MPEG-PS end scan loop forever), a probe that read gigabytes when a file has no sequence header, and a wrong duration when the last 128 KiB holds no timestamp. Files of 4 GiB or more are still sized wrongly on those drives. Keep files below 2 GiB until a console confirms the fix.

High-bitrate USB stutter — #24

On 2026-11-02 the reporter tested 8a25e22: on USB they described a slight slowdown at about 0:10–0:16, MX4SIO still stuttered, and seeking backward after pausing froze playback. 2.9rev4 played the same USB video smoothly. That build has PR #49, which reads confirmed-USB files ahead on a helper thread in up to four 64 KiB slots. PR #51 (c275476) stops the playback workers before a scrollbar seek; it has not been retested on a console. Unknown/non-USB mass devices retain 4 KiB reads and 32 KiB refills; the MX4SIO workaround is preserved. Host controls establish routing, byte continuity and bounds; console throughput is unmeasured. Compare the identical file, source and settings with matched DIAG read/refill and queue measurements before calling the stutter resolved. PR #55 fixes Rewind (LEFT) near the start exiting playback, a forward scrollbar seek stopping AVI/MP4 playback when no keyframe follows the target (a regression from PR #51), MPEG-PS seeks landing on non-I pictures and stale pause counts after a seek, and adds a peak-bitrate cap to the converter's MPEG-1/2 presets. It does not change MX4SIO reads; that waits for the DIAG throughput measurement.

Green or red video color — #20 / #23

Green color and red fluctuation have newer paired recordings and converter logs. Conversion success does not establish correct console output. The exact failing MPG bytes/hash are still needed. The PR #55 investigation found no remaining decoder defect: #23's fluctuating colour matches a motion-compensation bug inherited from 2.9rev4 and fixed on master after the reporter's last test, and nothing on PC reproduces #20's green cast. Both need a retest on a current build with a freshly converted file.

The MPEG RGB ownership fix removes a reproduced held-buffer overwrite. Longer controls in PR #35 exposed signed chroma-vector rounding, XY interpolation and field-row order defects. Their fixes pass a native C/DMA/MMI and field-output oracle; unchanged 150-frame MPEG-1/2 inputs have substantially lower error in both 16/32-bit output. The field-row fix also removes all channel differences over 32 levels in the interlaced B-picture control. Read the measured decoder report for scope and residual errors. These controls exclude the affected console's full display path. Test the unchanged failing MPG, pause/resume, seek, stop and sequence changes on the affected setup. No blanket BT.601/range transform is supplied. PR #41 changed MPEG-1/2 converter presets from GOP 50 to 15 to shorten prediction chains. Existing converted files are unchanged: re-convert the same source and compare both encodes on the affected setup. This is a mitigation candidate; the specific reconstruction-drift explanation and a complete color fix are not established by host or packaging tests.

MP4 late start and stall — #10

The reported 0:28 start and 0:35 video/audio-loop stall remain unconfirmed. MOV packet selection, offsets, timing tables, co64/extended atoms, allocation ownership and failed sample reads have host-tested fixes. PR #42 additionally rejects incomplete variable sample-size tables, with production-reader truncation controls. This does not establish faster opening. Obtain the exact original and converted files and test both ordinary and fast-start layouts through the full player. Faster opening alone does not demonstrate that the stall is fixed. Separately, PR #46 makes AAC that decodes with implicit upsampling report its real output rate; a low-rate AAC track that played at the wrong length is worth retesting on Rev.3. PR #55 fixes the MP4 video sample entry being read 2 bytes short (so the MPEG-4 setup header was never parsed), packet-order choices that forced backward seeks and restarted USB read-ahead, an edit-list check that rejected whole MP4/M4A files (a regression from Rev.1), B-frame MP4 timestamps, and PAL 2:2 pulldown forcing the wrong MP4 time base.

Saved skin after restart / Spanish — #27

Skin persistence still needs the reporter's USB save/restart test. The late-configuration repaint and skin bounds/allocation paths were fixed, and the Spanish strings were integrated. Test default PAL/NTSC, a non-default output mode and card/USB launch paths; check Spanish glyphs and label clipping separately. HD gradient behavior is not the same issue. PR #55 fixes the saved skin and display mode not being applied when settings load from the memory-card fallback (every HDD boot), the skin, wallpaper and splash vanishing at SD widths 641–720, the SELECT+R1/R2 video-mode rescue being undone on USB and MMCE boots, the splash replaying on every desktop rebuild, late display settings not applied at boot, and the Language row reporting a valid pack as bad after CD, host or SMB boots.

Folder shuffle — #25

Folder shuffle is implemented, with failed-open and playlist-lifetime regressions covered on the host. Enable Randomize playlist under Player settings → MP3 settings, then use Play all → Video. Check every eligible item appears once, Stop/next behavior, missing/unreadable files and a large folder on console. PR #55 fixes a permanent hang when Randomize playlist meets two entries with the same title in an .m3u or a Play all → Audio folder, a biased first shuffle pick, and a same-named .srt/.sub/.txt left open as a subtitle during continuous audio. Shuffle from a single track picks each next track at random and runs until you stop it (see Audio).

Converter tracks and subtitles — #22

Multi-audio, text burn-in, source-SD sizing and the high-quality Xvid/PCM preset are implemented and host-tested. SMS audio switching, SD aspect/display and high-bitrate playback on suitable storage remain acceptance work. Switchable embedded text, sidecar export and bitmap conversion are separate from the implemented burn-in control. PR #43 caps converter output below 2 GiB so files stay seekable, and PR #46 limits AVI audio choices to codecs the converter actually writes. PR #55 limits the MP4/M4A codec choices to ones the player decodes and FFmpeg can write, makes the FLAC preset write stereo 16-bit files the player accepts, and fixes the MP4 video sample-entry read shared with #10. BT.709 sources are still encoded with the BT.709 matrix while the PS2 decodes BT.601; that is unchanged and is not the #20/#23 defect.

Poster / cover-art grid — #26

PR #34 merged an optional R2 JPEG cover grid for #26 into master at 3eab0ee. Same-directory, same-basename JPEGs supply covers through a six-thumbnail cache; missing or unsupported artwork uses normal icons. See setup, limits and controls. Lookup, cache, navigation, packet and lifecycle behavior have host controls. Merged follow-ups through PR #40 also cover long browser/HOST/M3U paths, navigation allocation failures and failed device entry, and PR #45 redraws rebuilt entries during reload. PR #52 hides a video's same-name JPEG from the list and PR #53 adds a selected-poster view to the R2 cycle. Master includes PR #35's playback fixes; console rendering, device removal, repeated navigation/playback transitions and resource-stability acceptance remain pending. PR #55 fixes R2 or Triangle back to the list view leaving the cursor able to move off-screen, and Circle (choose subtitles) in grid or poster view re-decoding the artwork just before playback and keeping its cache while the video plays. #26 remains open.

How to read validation claims

EvidenceWhat it establishes
Host tests / sanitizersSpecific C/Python behavior with fixtures and controlled interfaces; not PS2 scheduling, bus throughput or display output.
PS2 target build / ABI checksCompilation, linking and checked module imports; not actual device operation.
Controlled PCSX2 probesOnly the exercised decoder, buffer, IPU and scheduling paths; not a full console playback result.
Real-console comparisonThe recorded console, source, media bytes, build and settings. Do not generalize a passing profile to every encode or transport.

For the detailed reproductions and next-agent work, read the engineering handoff and color-control report. Use the reporting checklist for a new result.
